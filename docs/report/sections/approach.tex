The auditor is a Python package with six steps (Figure~\ref{fig:pipeline}). (1) The policy text is split into
clauses with ids we can cite, and we rewrite them by hand into requirements. (2) The repository is cut into overlapping
pieces of 40 lines and indexed for BM25 search~\cite{robertson2009bm25}. (3) A keyword search (plus one LLM call in the
LLM modes) sets the AI Act risk tier. (4) The risk tier decides which requirements apply; no model is involved here.
(5) The rules, the LLM judge or the hybrid decide each applicable requirement. (6) A citation check validates every
answer, and the result is written as a JSON and a markdown report.

The benchmark contains deliberate \emph{traps}:
\begin{itemize}[leftmargin=*]
  \item \textbf{for rules, indirect evidence:} logging done by a \texttt{DecisionJournal} instead of a logger, or a kill
        switch called \texttt{suspend\_automated\_ranking};
  \item \textbf{for rules, decoys:} a commented-out \texttt{\# logger.info(...)}, \texttt{override\_allowed = False}, a
        TODO to label AI replies;
  \item \textbf{for LLMs:} README claims that the code does not back, and controls that exist but are not enough (a
        data retention period that is too long).
\end{itemize}

\subsection{The three decision methods}
\label{section:methods}

\paragraph{Rules.} Each requirement has one or more checks: a text pattern that must be present (or absent) in some
files, or a file that must exist. If all checks pass, the answer is compliant; if none pass, non-compliant; if some
pass, partial; if none can run, needs review. In v0 the confidence is fixed for each status (0.9 for compliant, 0.8 for
non-compliant, 0.5 for partial, 0.2 for needs review). The patterns read raw text, so a commented-out line counts as
real code.

\paragraph{LLM judge.} We use Claude Sonnet without examples or training (zero-shot), called through the Claude Code
command line~\cite{claudecode} with all tools turned off. For each requirement it receives the requirement text and at
most 14 evidence pieces found by search, each with a short id (\texttt{E1}, \texttt{E2}, \dots). It must answer in a
fixed JSON format: status, confidence, explanation, cited ids, gaps and a suggested fix. It may decide only from the
pieces it sees, and is told that ``absence of evidence is not compliance''.

\paragraph{Hybrid.} The rules run first. The LLM is asked only when the rules are unsure: their answer is partial or
needs review, their confidence is below 0.75, or the requirement has no checks. All other rule answers are kept. If
rules and LLM give opposite answers (compliant against non-compliant), the item goes to needs review; otherwise the LLM
wins. Any answer that involves the LLM and has confidence below 0.6 also goes to needs review. Because the v0 rule
confidences are fixed, in practice only partial and needs-review rule answers reach the LLM.

\paragraph{Citation check.} After every answer, a small program removes cited ids that were never shown. If an LLM says
compliant or partial and no valid citation is left, the answer becomes needs review.

\subsection{Training and testing}
\label{section:training}

Nothing is trained. We wrote the rules by hand from the policy text, the LLM is used zero-shot, and the two thresholds
(0.75 and 0.6) were fixed before the experiments. We wrote all 225 labels before running any method, so they are a pure
test set; there is no training or validation split. The main risk is that the same team wrote the rules, the prompt and
the apps. To limit it, we labelled first, planted traps against our own rules, and changed nothing after seeing the v0
results.

\subsection{Validation and comparisons}
\label{section:validation}

The three methods get the same requirements, evidence, search results and risk tier. Only the decision step changes,
so any difference in the results comes from it. ``Rules only'' stands for policy-as-code, ``LLM only'' for an LLM
judge, and the hybrid is our combination.

\subsection{A worked example}
\label{section:example}

Take requirement \texttt{AIA-REC-01} (Article~12, automatic logging) on the app \texttt{hireright-screening}. The
true label is compliant: every ranking is recorded by \texttt{DecisionJournal.record(...)}. The app is high-risk, so
the requirement applies.
\begin{itemize}[leftmargin=*]
  \item \textbf{Rules:} the logging pattern finds no logger, so the answer is non-compliant with confidence 0.8 (wrong).
  \item \textbf{Hybrid:} 0.8 is not below 0.75, so the rule answer is kept and the LLM is not asked (wrong).
  \item \textbf{LLM only:} the search finds \texttt{journal.py}; the judge says compliant (0.82) and cites 5 pieces
        (right).
\end{itemize}
The lesson: a fixed rule confidence makes a pattern that found nothing look as sure as one that found something.

\section{Numerical validation}
\label{section:numericalValidation}

\subsection{Methodology}
\label{section:methodology}

We test three hypotheses:
\begin{itemize}[leftmargin=*]
  \item \textbf{H1:} the LLM judge finds more gaps than the rules;
  \item \textbf{H2:} the hybrid is more accurate than both, and cheaper than the LLM alone;
  \item \textbf{H3:} the rules are fooled by decoys and miss indirect evidence.
\end{itemize}
We change the decision method and measure the metrics of Chapter~\ref{chapter:problem}. Each method audited the five
apps against all 45 requirements once, on an Apple M4 laptop (16\,GB); LLM answers are cached so a run can be replayed
exactly. For uncertainty we use 95\% bootstrap confidence intervals (10\,000 resamples of the 165 items). To compare two
methods on the same items we use the McNemar test, which looks only at the items where one method is right and the
other is wrong.

\subsection{Data}
\label{section:data}

The test set is the benchmark of Table~\ref{tab:data}. A label is \emph{compliant} if every part of the requirement has
evidence, \emph{partial} if some parts do, and \emph{non-compliant} if none do. Claims, TODOs and commented-out code are
not evidence. \emph{Not applicable} is used only when the risk tier excludes the requirement, so it is never a judgement
call.

Table~\ref{tab:main-results} and Figure~\ref{fig:v0-modes} show the results. The hybrid is the most accurate and
costs 14\% of the LLM-only run. It is significantly better than the rules ($p<0.001$: it fixes 11 items and breaks
none) and than the LLM ($p<0.01$); rules against LLM is not significant ($p=0.15$). The 18 items that the hybrid sends to
the LLM reach 94.4\% accuracy. The LLM alone flags all 65 gaps, while rules and hybrid miss the same 8 ($p<0.01$). But
only 60.8\% of the LLM's flags are real gaps. The keyword risk tier is right for 4 of 5 apps, the LLM tier for all 5.
All citations are valid for all methods.

\paragraph{Error analysis.}
\begin{itemize}[leftmargin=*]
  \item \textbf{Rules fooled by decoys:} 4 of the 8 rule false compliances come from a commented-out logger,
        \texttt{override\_allowed = False} and a TODO note.
  \item \textbf{Rules miss indirect evidence:} 10 compliant items are called non-compliant because the code uses other
        names (\texttt{DecisionJournal}, \texttt{suspend\_automated\_ranking}, ``pseudonymous'').
  \item \textbf{LLM too strict:} 41 of its 47 errors are compliant items called partial. The prompt does not say what is
        ``enough'', and cut-off evidence counts as missing.
  \item \textbf{Hybrid inherits rule errors:} 22 of its 23 errors are confident rule answers that never reached the LLM.
\end{itemize}

\section{Discussion}
\label{section:discussion}

\begin{itemize}[leftmargin=*]
  \item \textbf{H1 supported:} gap recall 100\% against 87.7\%, but with 42 false alarms against 16.
  \item \textbf{H2 partly supported:} best accuracy at 14\% of the LLM cost, but the false-compliance rate stays at
        12.3\%, and the macro-F1 differences are within the intervals.
  \item \textbf{H3 supported:} decoys cause half of the rule false compliances, and indirect evidence causes 10 errors.
\end{itemize}
\emph{Strengths:} rules are free, instant and precise when a requirement has a clear text pattern; the LLM reads code
and prose and is not fooled by decoys; every answer points to its evidence. \emph{Weaknesses:} the fixed rule confidence
carries no information, so the hybrid cannot catch rule errors; the LLM is too strict; and the benchmark is small (the
intervals are about $\pm5$ points), synthetic and labelled by us.
