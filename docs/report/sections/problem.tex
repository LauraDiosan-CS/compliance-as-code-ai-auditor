\chapter{Scientific Problem}
\label{chapter:problem}

\section{Problem definition}
\label{section:problemDefinition}

\paragraph{Informal description.} An auditor must answer one question for each obligation: does this application do
what the law asks, and where is the proof? This is hard for three reasons:
\begin{itemize}[leftmargin=*]
  \item \textbf{The law is not code.} Article~12 asks for ``automatic recording of events''. In code this can be a
        \texttt{logger.info(...)}, a custom \texttt{DecisionJournal.record(...)}, or nothing at all, even if the README
        says it exists.
  \item \textbf{The proof is scattered.} It can be in code, configuration, infrastructure files or documents.
  \item \textbf{Traps are common.} Commented-out code, TODO notes and marketing claims look like proof, but they are not.
\end{itemize}

\paragraph{Why an intelligent method?} Deciding whether some evidence satisfies a vague legal sentence is a
reading-and-reasoning task, and LLMs are the best current tool for it. There is no labelled dataset to train a
classifier, so we compare two realistic options and their mix. Rules are cheap, repeatable and easy to explain, but
brittle. An LLM is flexible, but costs more, can give different answers, and may invent evidence.

\paragraph{Formal definition.} The \textbf{inputs} are a policy and a repository. The policy is split into clauses, and
we rewrite them into testable requirements. The repository is split into pieces of evidence. For each requirement, the
\textbf{output} is:
\begin{itemize}[leftmargin=*]
  \item a \textbf{status}: compliant, partial, non-compliant, needs review or not applicable;
  \item a \textbf{confidence} between 0 and 1;
  \item the \textbf{cited evidence}: file and lines.
\end{itemize}
Every answer must follow three rules:
\begin{enumerate}[leftmargin=*]
  \item a requirement is \emph{not applicable} only if the application's risk tier excludes it;
  \item the method may cite only evidence that it was shown;
  \item it may never say \emph{compliant} (or partial) without evidence.
\end{enumerate}
``Needs review'' means the method does not decide and a human takes over. The worst error is \emph{false compliance}:
a real gap that we wrongly call compliant.

\paragraph{Metrics.} We score only the applicable requirements. A \emph{gap} is a requirement that is truly partial or
non-compliant.
\begin{equation}
  \text{accuracy}=\frac{\#\,\text{correct statuses}}{\#\,\text{applicable requirements}},\qquad
  \text{false-compliance rate}=\frac{\#\,\text{gaps called compliant}}{\#\,\text{gaps}}.
\end{equation}
We also report macro-F1 (the average F1 over compliant, partial and non-compliant), \emph{gap recall} (the share of
gaps we flag) and \emph{gap precision} (the share of our flags that are real gaps), whether the risk tier is right,
whether the citations are valid~\cite{gao2023alce}, and the cost: LLM calls, dollars and seconds.
