\chapter{State of the art/Related work}
\label{chapter:related}

We found no published system that checks a whole application repository against a regulation on a public benchmark.
Related work solves neighbouring problems, grouped below.

\section{Policy-as-code}
\label{section:rel-pac}

Tools such as Open Policy Agent~\cite{opa} write rules as code and check them on structured files, for example
deployment or cloud configurations. Static analysis tools report their findings in a shared format,
SARIF~\cite{sarif2020}. These rules are fast and exact, but they only see text patterns.

\paragraph{Difference.} Our rules are linked to legal clauses, and requirements that no pattern can check go to an
LLM. On data governance, rules alone reach 35.7\% accuracy in our benchmark and the LLM 92.9\%.

\section{Compliance checking of legal documents}
\label{section:rel-nlp}

Torre et al.~\cite{torre2020completeness} and Amaral Cejas et al.~\cite{amaral2023dpa} use NLP and machine learning to check
privacy policies and data processing agreements against GDPR. LegalBench~\cite{guha2023legalbench} tests how well LLMs
reason about legal text.

\paragraph{Difference.} We check code, configuration and documents, not only documents, so we can catch a README that
promises something the code does not do. We also measure false compliance, the error that matters most for an auditor.

\section{LLMs as judges, with retrieved evidence}
\label{section:rel-llm}

Retrieval-augmented generation lets an LLM answer from passages found by a search engine~\cite{lewis2020rag}; we use the
classic BM25 search~\cite{robertson2009bm25}. LLMs are also used as judges, but they have known biases~\cite{zheng2023judging}.
They can state things that the sources do not support~\cite{ji2023survey}, so newer work checks whether each claim is
backed by a cited source~\cite{gao2023alce}.

\paragraph{Difference.} Our judge may cite only the evidence it was shown, and a simple program checks this on every
answer, for free. In v0, 100\% of the citations are valid.

\section{AI Act and AI auditing}
\label{section:rel-audit}

Veale and Zuiderveen Borgesius~\cite{veale2021demystifying} analyse the AI Act and show where its text is vague.
M\"okander et al.~\cite{mokander2023auditing} propose to audit LLM systems at three levels: the company, the model
and the application. Both works are written for people who do the audit by hand.

\paragraph{Difference.} Our audit is automatic and runs on the application itself, so it can be repeated after every
commit.
